## 1. 设计原则

### 1.1 读者与目标

入口基础为 Python 的变量、函数、循环、基本容器，以及中学代数、函数、指数对数和三角知识。绘图、数组操作及 Notebook 的使用在首次需要时给出最小示例。大学数学不作为入学前提。

全书终点是：**核心方法能够推导、实现和验证；精选现代方法能够完成小规模研究复现，并解释适用条件与失败原因。** 全书按 17 篇、85 章规划。前五篇保留“建模—动力学—非线性—概率”的篇序，第 4 篇补充吸引子的统一语言并新增 4.6 连续时间混沌与奇异吸引子，前五篇共 23 章；新增数学在首次需要的章节完整引入。

读者沿同一条推荐路线学习，逐步掌握：提出问题和模型假设；从机制写出更新规则；理解必要的数学推导；实现和检查模型；从数据辨识与估计；设计干预；解释群体现象；复现和比较研究方法。

每种方法首先讲清所解决的问题、适用假设和可检查的结论。核心推导进入正文，较难的证明放入拓展，并说明省略的证明为何不影响当前学习任务。后续核心章节不得把拓展材料当成未说明的先修条件。

### 1.2 内容与形式

- 人体与生命系统是主要案例，案例所需的生理、细胞或生态知识随章解释。
- 数学从实验问题中引入，首次完整说明，随后以同一概念解决更复杂的问题。
- Notebook 承载完整教学、题面与本地样例；每篇按章设置独立网页，提供可视化解释、按需 playground 和交互练习入口，并链接回对应 Notebook。
- 所有习题只有选择题与提交 Python 代码的计算题；选择题提交后显示判定和详细解析，计算题由本机程序启动教材环境中的独立 Python 子进程执行并反馈结果。
- 整个项目面向本地学习，题库随教材提供，作答记录保存为 JSON，进度从记录汇总；依赖和材料准备好后可离线运行，不要求远端 worker 或数据库。
- 教学包只封装已经讲解且反复出现的公共需求；核心算法保留可读的显式实现。
- 教材使用通过验收的数据，运行过程与外部数据制备工具完全独立。
- 每篇都有综合任务；每个结论标明来自推导、数值证据还是经验性解释。

### 1.3 编号与推荐顺序

章节使用“篇.章”编号，例如 `3.2`；章节可以包含多个小节，每个小节对应一个独立执行的 Notebook。正式全书按 1.1 到 17.4 顺序导航。

全书目录每张篇卡片标注“第 N 篇”，篇目录每张章卡片标注“篇.章”，同时显示名称；侧栏使用相同编号。篇章顺序属于学习导航，S01/E01 等内部维护编码不向读者展示。目录布局紧凑，篇卡片给出章节主题，章卡片给出目标与先修，避免单行内容被大面积空卡片包围。

网页主体按浏览器可用空间展开，目录可隐藏和调宽；题目与代码分栏可调，长文本和代码默认自动换行。布局与显示行为以[网页规范](网页设计规范.md)为准；软换行不改变代码内容，不向教材的学习目标区加入这些操作说明。

下列章表的“先修章”列给出直接依赖，读者还需要这些章节的递归先修内容。“入口”表示只有前述 Python 和中学数学基础。数学编号对应[数学索引](#math-prerequisites)；首次引入该数学的章节在进入应用前完成解释与练习。参考资料编号均指向[参考表](#references)，作为编写和核查依据，不要求读者先读完原教材。

### 1.5 深度与独立核验的最低范围

| 方法主线 | 核心教学范围 | 独立核验与失效实验 | 后续使用 |
|---|---|---|---|
| 递推辨识 | 批量正规方程、秩一更新、递推最小二乘、遗忘及初始权重 | 相同正则/衰减的批量解对照；固定参数、缓慢漂移、弱激励；逆信息矩阵须在声明的误差与回归量条件下才解释为参数协方差 | 6.6 → 16.3 |
| 状态估计 | 一般贝叶斯预测—更新、离散隐状态、线性高斯、扩展/无迹近似、粒子方法、平滑与缺测 | 枚举或联合高斯参考；数值积分、权重退化、传感器不足、噪声失配；实时滤波不使用未来观测 | 第 7 篇 → 9.4、10.7 |
| 近似推断 | 后验局部近似、马尔可夫链采样、均值场变分及期望最大化、后验预测 | 共轭/低维积分参考；比较均值、方差、预测、诊断和计算代价；保留多峰、局部最优与模型失配 | 第 8 篇优化 → 第 9 篇 → 第 15 篇可微计算 |
| 现代建模 | 低秩、动态模态、有限字典、稀疏方程、可微动力学与机制融合 | 显式核心实现、完整/线性/稀疏传统基线、留出轨迹及失败实验；梯度对照有限差分，结构与外推单独验证 | 第 14—15 篇 → 16.7、17.2 |

### 4.3 学习目标、练习与评价设计

**先定义能做什么，再安排内容和证据。** 每篇大纲以 T1、T2 等标识可检查目标，并映射到具体客观题；编号只在本篇内使用。概念与解释目标转为明确场景下的判断和选项辨析，实现与迁移目标转为指定契约下的 Python 计算。所有核心目标都要有题目覆盖，不能只凭打开页面或看过演示认定掌握。

每章按“问题与事前预测 → 所需数学桥接 → 显式实现 → 对照和边界 → 解释与迁移”组织教学。大纲列出的内容顺序落地为独立小节；不把关键概念只放在可选网页或拓展阅读中。人工参数、领域简化和变量含义在实验开始前说明。

| 学习角色 | 允许题型 | 学习者提交 | 判定与反馈 |
|---|---|---|---|
| E1：概念、推导与手算辨析 | 选择题，按题目声明单选或多选 | 稳定选项 ID 或 ID 集合 | 完整集合判定，提交后显示正确项、逐项解释、推导和复习入口 |
| E2：实现与数值核验 | Python 计算题 | 按题目具名参数签名编写的 `solve` 源代码 | 本机子进程逐项传参执行样例及补充测试，检查结构、数值、误差、性质或约束 |
| E3：迁移与适用范围 | 选择题或 Python 计算题 | 场景方案选项，或适用于未见输入的代码 | 选择题解释各方案条件；代码题用不同参数、初值或结构客观判定 |
| 篇末综合任务 | 共享案例下的两类题组成题组 | 各子题分别提交选项或代码 | 按[篇末分层评分](#capstone-assessment)检验成果；所有必做题通过才记为完成，子题输入独立 |

E1—E3 只作为维护者的设计索引，不是学生可见编号。**每节 3—5 题**，一般小节 3 题，重难点 4—5 题；覆盖概念、计算与迁移，不以重复同类题凑数。各章 E1—E3 设计是骨架，不是最终题量上限。正式稳定题号、版本、题面/核验材料与本地 API 统一遵循[判题系统设计](交互练习与判题系统设计.md)。题面给出已知量、单位、允许改动、输入输出、误差与实际运行限制；多解问题按可行性、目标值或等价性质判定。无法稳定客观判定的内容必须重设计为有限选择或更小的计算任务。

| 教学质量维度 | 选择题的检查方式 | Python 计算题的检查方式 |
|---|---|---|
| 问题与模型 | 选项明确假设、单位与观测；干扰项对应可解释错误 | 题设模型明确，边界输入与守恒测试能拒绝错误模型 |
| 数学与实现 | 每个选项有依据，推导条件和中间步骤可核对 | 参考解与独立依据相互核验，允许符合契约的不同实现 |
| 验证与实验 | 辨认无效对照、单次轨迹推论和数据泄漏 | 测试覆盖边界、失效、形状和数值；随机判定可复现且经校准 |
| 解释与迁移 | 给出新场景和具体结论，判断适用范围 | 补充测试改变参数、初值或结构，不能只硬编码公开样例 |
| 复现与反馈 | 提交后完整解析；修改选项不沿用旧判定 | 题目、代码、环境和测试版本绑定；结果与提交快照对应，补充用例可展开复盘，系统故障不判答错 |

上述是教材和题库的发布质量检查，不是另设主观作业评分。选择题需审查歧义与逐项解释，代码题需运行正确参考解及典型错误解；没有完整选项、判定规则和核验材料的题只标记为设计中。若尚未试学，难度和学习时间仍为设计判断。

读者可以先预测或手算，再选择或提交代码。辨识和预测的核验答案不进入拟合输入；题面与补充测试分开组织，后者提交前不在界面展开、提交后可复盘。全部材料保存在本机，这种教学安排不承诺答案保密。观测和核验答案的分离继续遵循[数据验收](#data-contract)，反馈、随机判定与本机执行限制见[判题系统设计](交互练习与判题系统设计.md)。

计算题按“任务 → 具名参数函数签名 → 参数说明 → 返回值 → 计算规则 → 约束 → 输入/输出样例及解释”编写。例：`solve(A0, durations, inflows, outflows)` 直接返回物质量列表。题面、模板和判题器共用同一参数定义，不允许用 `payload`、通用 `data` 或可变参数掩盖输入。单一结果直接返回相应类型，多项结果明确命名和次序。

输入样例、输出样例分别包含直观解释与可复制 Python 代码。表格解释变量、单位、顺序与数值；输入代码逐个赋值后按签名调用函数，输出代码给出预期返回结构及原始精度数值，按题面容差对照。每组样例解释至少一个关键计算步骤。网页与 Notebook 从同一份样例生成两种表示，不能把通信对象当输入接口，也不能只留表格而省略代码。示例代码用于理解契约与试算，核心算法仍由读者实现。

### 4.4 篇末综合习题的梯度与评分

本节是全书篇末综合习题的统一评价规范。**仅适用于篇末题组，章内习题的题量、题型、判定和进度保持现状。** 各篇大纲维护本篇案例、具体任务、目标映射与分值分配；网页和判题文档只维护呈现与实现契约。

#### 难度递进与分值

每篇综合题组满分 100 分，按下表从易到难排列。首轮采用八道独立子题，每层两题；每道题只有一个提交入口和明确的客观判定。选择题与 Python 题可以出现在不同层次，不能用题型、代码长度或算量直接代替难度判断。

| 层次 | 要检验的能力 | 支持程度与任务边界 | 题数与分值 |
|---|---|---|---|
| 1 基础辨析 | 识别问题、变量、单位与成立条件 | 单一情境，提供完整已知量；判断一项核心关系 | 2 题 × 10 分 = 20 分 |
| 2 方法应用 | 按本篇已学方法完成计算或解释 | 给定明确模型或规则，在多组输入上应用，并处理基础边界 | 2 题 × 15 分 = 30 分 |
| 3 综合验证 | 连接多个概念，组织计算与独立核验 | 组合本篇两项以上内容，比较结果、误差或证据；保留失效情形 | 2 题 × 15 分 = 30 分 |
| 4 迁移挑战 | 在条件变化后重新计算并限定结论 | 改变观测、输入、约束、结构或评价条件；所需知识仍来自本篇及先修 | 2 题 × 10 分 = 20 分 |

最高层检验迁移，分值保留为 20 分，使基础与方法应用仍占一半。增加难度应减少现成步骤、增加有意义的条件组合，而非加入未教知识、冗长编程或模糊题意。题面始终明确输入输出、单位、允许库、误差及边界。每题提供完整输入或固定中间结果，前题答错不能使后题无法作答；页面可按建议顺序学习，也允许直接跳题。

每道题指定一个**主要计分目标**，用于把分数分配到本篇 T1—T4；可以另列相关目标，但同一分值不重复累计。四个目标均需有证据。分层分数与目标分数分别加总到 100，目标之间的满分可能不同，页面显示“已得分 / 本目标满分”，不把不同目标的绝对分数直接排名。

#### 客观计分与成绩含义

选择题的选项集合完全正确、Python 题完整测试全部通过时，得到该题全部分值；其余有效完整提交记 0 分。不按通过用例比例给部分分，不设倒扣、速度奖励或少重试奖励。若需要更细的诊断，应拆成独立子题；用例类别和错误解释用于定位问题。语法错误、运行错误、超时、输出超限都是一次有效完整作答中的未通过结果。

| 成绩或状态 | 汇总规则与用途 |
|---|---|
| 首次作答分 | 各题当前版本最早一份已保存的有效完整提交的得分之和；后续改正不覆盖它，用于观察初次表现 |
| 练习达成分 | 各题当前版本只要曾完整通过便取得该题分值，每题最多累计一次；反映经过练习已经完成哪些任务 |
| 未作答 | 暂不增加分数，单独显示未作答题数；首次分在所有题都有有效完整提交后才给出整组等级，不能把未答直接解读为不会 |
| 题组完成 | 本版本所有必做子题均完整通过；达到某一分数等级不替代完成状态 |

“用示例试算”、取消、中断、系统故障、未保存结果不进入任何一项成绩，也不占用首次有效作答。重复请求只对应一次记录。成绩以本机已保存的记录为证据，首次分并非闭卷成绩：本机无法保证学习者未看过题解、提示或外部材料；选择提交后照常立即显示完整解析，Python 提交照常显示测试结果。练习达成分与首次分必须并列标明，不能用反复重试后的满分宣称独立掌握。

#### 等级与复习建议

对已完成首轮的首次分、以及当前练习达成分分别应用同一诊断尺度。后者在首次尝试之前只显示“尚未开始”；已作答但尚未全部通过时，仍显示未完成题数。

| 总分 | 诊断等级 | 基础条件 |
|---|---|---|
| 0—59 | 需巩固基础 | 优先回看最早未通过层次的概念和示例 |
| 60—79 | 基本达标 | 基础辨析 20/20，且方法应用至少 15/30 |
| 80—89 | 掌握良好 | 同上，并结合综合验证的失分定位薄弱环节 |
| 90—100 | 综合表现扎实 | 同上；根据迁移题检查适用范围与边界 |

总分达到 60 但基础条件未满足时，显示实际总分与“基础环节待补齐”，不判为达标。等级是教材设计的自学诊断尺度，尚未经目标读者试学校准，不作为认证或跨篇能力排名。展示四层分数、各目标分数和未通过题目，按层次优先给出答题及对应章节复习入口；达成满分后可以自行重新练习，首次记录仍保留。

例如：首次仅通过基础两题、应用一题和综合一题，首次分为 50/100；订正后全部通过，首次分仍为 50，练习达成为 100，题组完成。若仅错一道基础题而其他全对，总分为 90，仍提示基础环节待补齐。两例都不能仅凭总分隐藏具体缺口。

#### 版本与发布检查

题面、选项、函数契约或判定实质变化时升题目版本；旧作答保留，但不计新版成绩。只增加计分元数据而题意不变时，同版本历史记录可以汇总，须说明包含评分启用前记录。首次指本机可读取的最早保存记录，不为加入评分而清空历史；题组组成和分值另有评分版本，换版后的汇总须显示版本，不宣称与旧卷直接可比。损坏记录使成绩标记为不完整，不把缺失记录解释为首次作答。

发布时检查四层顺序、各层分值与总分、全部目标覆盖、独立输入、正确解及典型错误解；同时实际验证错误后订正、样例不计分、版本隔离、刷新与重启恢复。评分实现、存储和页面分别遵循[判题设计](交互练习与判题系统设计.md#capstone-scoring)及[评分呈现](网页设计规范.md#capstone-score-ui)。

## 5. Notebook 与网页教学规范

### 5.1 教学内容与制作信息的边界

每节开头只包含标题、可检查的学习目标、直接先修知识与必要的复习入口。案例在“具体问题”引入，变量与简化范围在“模型假设”说明，实验成果、练习和参考资料放在对应位置，不把全部制作信息堆入开头。

网页安排、模板说明、软件职责、制作状态和验收计划属于设计与维护文档；安装、内核选择、启动程序和故障恢复属于 [README](../README.md#run-m1) 或[学习指南](学习指南.md)。这些内容不得写入“学习目标与先修知识”。导入和绘图设置代码在首次实验之前提供，不以大段操作说明打断问题引入。

每章必须有独立网页和章内/篇末交互练习入口。可视化模块在设计文档中逐节标注为“不新增可视化模块”“可视化解释”或“可视化与 playground”，说明教学理由；这一制作决定不复制到学习目标中。章节编号确定阅读顺序，实际链接随交付建立，设计文档中不放指向尚不存在文件的可点击运行链接。

### 5.2 Notebook 的必备结构

1. **学习目标与先修知识**：仅给出可检查的学习目标、直接先修知识及必要复习入口。
2. **具体问题**：用生命系统现象说明本节的研究问题，解释必要的领域知识。
3. **初步实验**：让读者先观察少量、容易解释的现象，代码保持简短。
4. **模型假设**：列出变量、单位、输入、初值、边界、时间尺度及简化条件。
5. **数学解释与推导**：从当前问题引入必要概念；每个新符号首次出现时定义。
6. **核心实现**：先展示机制或算法的必要步骤，再说明成熟库如何完成同一工作。
7. **对照实验**：一次改变清楚的条件，并包含至少一个边界或失效情形。
8. **结果解释**：区分模型机制、数值误差、观测限制和统计不确定性。
9. **练习与参考资料**：仅用选择题和 Python 计算题覆盖概念、实现与迁移；保留完整选项或函数契约、公开样例和提示，每题链接到带题号的实际答题页面。概念、解释、迁移是学习角色，不另设解释题、报告题或自由文本题。独立核验规则与题库版本一致。

每节可从新内核单独执行。概念学习依赖先修内容，代码执行不依赖前一节残留变量或手工操作。关键状态、导入、数据加载与图形设置在本节或已安装教学包中明确提供。

### 5.3 数学与科学论证要求

- 直觉图、数值例子和数学推导相互对应；仿真图不能替代稳定性、因果性或普遍性证明。
- 数学结论写明成立条件；局部结论不扩展为全局结论，线性近似不隐含覆盖远离平衡的状态。
- 术语写法遵循[专业术语首现与后续称谓](#terminology-style)。
- 在首次区分时解释状态与观测、存量与浓度、机制图与因果证据、参数可辨识性与状态能观性。
- 数值实验交代步长、精度、边界处理和收敛检查；保留用于解释失败的结果，不通过裁剪悄悄掩盖错误。
- 随机实验交代教学实验自身的随机设置、重复次数和统计误差；不能用单条轨迹证明统计规律。
- 领域案例记录教学假设和简化范围，数值示例中的人工参数不被描述为真实个体的测量或建议。

### 5.4 网页与 playground 的设计要求

网页按篇和章组织：每篇有首页及综合题组，每章有独立页面与交互练习入口。只有当动画、空间关系、图像联动或参数探索能够帮助理解时才增加相应可视化/playground 模块；这项判断不能用来省略章节页面。完整路由、布局、组件、响应式及可访问性要求见[网页设计规范](网页设计规范.md)。

| 设计项目 | 要求 |
|---|---|
| 学习问题 | 篇首页说明能力目标，章页面说明概念、先修、Notebook 位置和练习清单 |
| 交互练习 | 只有选择与 Python 计算两类输入；选择提交后显示详细解析，代码提交显示本机实际运行的判定、失败类型与用例差异 |
| 操作与反馈 | 控件有变量含义、单位和范围；操作实际改变相应模型、图示或结果 |
| 探索提示 | 提供少量有目的的比较，如“只改变初值会怎样”或“为何减小步长后振荡消失” |
| 解释与链接 | 网页请求默认 IDE 打开 Notebook 原文件；Notebook 的可视化与练习链接使用本机 HTTP 页面地址，点击后显示渲染网页，不使用相对 HTML 文件链接 |
| 模型一致性 | 同一模型共享可核对的数学定义和参数含义；不同语言实现以参考数值对照 |
| 视觉一致性 | 白底界面使用指定蓝红色系，代码编辑与调试输出使用 Monokai 深色配色；数据曲线采用独立的鲜蓝、玫红及扩展色板，同一案例的变量/方法在网页和 Notebook 中保持一致，详见[视觉与图表规范](网页设计规范.md#visual-design) |
| 简化与异常 | 简化条件可见；越界、非有限结果和数值失真得到说明，不显示为可信模型结论 |
| 可访问性 | 关键结论不只靠颜色表达；图有坐标和单位；控件能用键盘操作 |
| 教学连续性 | 本地网页程序未运行时，Notebook 的图示、解释、题面和样例仍完整；样例通过不等于完整测试通过 |

网页不承担独有的必要先修知识。浏览器负责编辑和反馈，现有本机入口按[本地运行设计](交互练习与判题系统设计.md#local-runtime)扩展页面与 API，提交代码在独立 Python 子进程中执行，不在页面进程或 Notebook 内核中执行。前端沿用 HTML/CSS/ES Modules，作答记录采用本地 JSON 文件；Notebook 可独立运行。普通子进程分离执行状态，不宣称安全沙箱或答案保密。

### 5.5 专业术语首现与后续称谓

专业术语首次出现时必须保留英文全称。先确定后文主要使用英文缩写还是规范中文译名，再采用以下格式；本节集中维护教材的术语规则，其他文档通过引用使用。

| 后文主要用法 | 首次出现格式 | 示例与后续称谓 |
|---|---|---|
| 主要使用英文缩写 | 英文缩写（英文全称，规范中文译名） | 首次写 MPC（model predictive control，模型预测控制），后文使用 MPC |
| 主要使用中文，且有领域共识缩写 | 规范中文译名（英文全称，英文缩写） | 首次写常微分方程（ordinary differential equation，ODE），后文使用“常微分方程” |
| 主要使用中文，且无领域共识缩写 | 规范中文译名（英文全称） | 首次写特征值（eigenvalue），后文使用“特征值” |

每个可独立阅读的教学单元在术语首次出现处就地标注，包括 Notebook 和章节网页；不能仅在另一个文件或篇末词汇表中给出英文。没有领域共识的缩写时只保留英文全称，不为凑齐格式自造缩写。英文全称与缩写的拼写、大小写采用领域通行写法，中文采用规范译名。首次引入还须解释概念的含义、用途和必要条件；全书保持术语对应关系一致，同一阅读单元后续使用选定的主要称谓。

题面、解析、图注和正文采用相同的术语对应关系；同一阅读单元内已经完成首次说明后，不必在每个控件或图例中重复长括注。编写与评审时检查首次标注是否完整、缩写是否通行以及跨材料称谓是否一致。

首次标注以阅读正文为准，包含学习目标中的概念；标题、目录和导航可使用简短称谓，正文第一次使用仍需标注。可直接打开的每道题按独立阅读单元处理。代码变量、通用操作按钮不为形式要求强加括注。[术语对照表](术语对照.json)记录当前教学内容的统一写法；扩展教材时同步补充，并人工检查未收入词表的新概念。

发布前执行[教材制作检查表](教材制作检查表.md)。正式课节的题面由同一题库同步至 Notebook，检查工具核对两类题、实际页面链接、目标区内容和已收录术语首现；渲染后的阅读体验和新术语仍须人工复核。

## 6. 教学包与数据验收

### 6.1 轻量教学包

包的职责限定为四类：读取已验收教学数据；统一绘图；组织重复实验；整理结果和检查量。接口使用 NumPy 数组、普通表格和绘图对象等常见类型，不要求读者先学习专用模型描述语言。统一绘图按[数据图表色板](网页设计规范.md#chart-colors)维护系列颜色、线型与标记，并与网页共享颜色定义；借鉴 SHAP 配色不增加 SHAP 依赖。

基础计算采用成熟科学计算库；控制、网络和优化章节分别按需使用相应库。基础环境不强制安装所有研究专题的依赖。公开函数与安装方式在实现后同时提供示例、运行验证和说明。

上述是长期能力划分；目前已经实现的接口和安装入口以 [README](../README.md#run-m1) 为准。教学包仅抽取已交付内容的公共需求；简单模型的更新式、数值循环与解析解保留在 Notebook 中供读者理解和修改。

### 6.2 数据接收边界

教学项目只接收已通过验收的数据文件及教学使用说明。文件可以由项目外部准备，但教材不导入、调用或依赖制备软件，不保存制备工具的身份、路径、配置、版本、生成种子、调用脚本或生成记录。

接受数据后，复现实验所需的是固定的数据内容、教学代码和实验环境。数据文件的教学名称、校验值、字段说明与质量检查结果可以随教材保存；它们描述数据本身。小型理想模型在 Notebook 中直接计算得到的轨迹属于课程实验，也不依赖任何外部制备工具。

### 6.3 数据文件必须说明什么

| 项目 | 必要说明与检查 |
|---|---|
| 数据内容 | 文件用途、行所代表的观测单元、变量名、类型、单位和有效范围 |
| 时间与个体 | 时间单位、起点、采样含义、是否规则采样、个体或序列标识、重复键的含义 |
| 质量 | 缺失值和特殊值含义、时间排序、重复记录、非有限值、取值范围与单位一致性 |
| 教学用途 | 适用的章节、可进行的任务、允许的使用方式和不能支持的结论 |
| 独立读取 | 采用常见文件格式，能在教材环境中直接读取，所需数据随本地教学材料提供或独立获取 |
| 文件一致性 | 固定数据文件的校验值；替换数据后重做质量和教学预期检查 |
| 答案隔离 | 观测和用于核验的答案分别存放、分别读取；答案不进入拟合与预测输入 |
| 验收结论 | 通过/不通过、检查日期、适用范围与已知限制；不通过的数据不进入核心实验 |

验收还要运行一个最小教学任务，确认数据确实足以支持该节目标。格式正确不等于能够支持参数辨识、状态恢复或机制判断；若缺少相应证据，应调整任务和结论范围。

后续实验自身使用随机抽样或随机算法时，记录该实验的种子和环境。这不增加对原始数据制备过程的记录或运行要求。

### 8.2 成熟方法与研究专题的标注

PID、状态反馈、Kalman、LQR、MPC，以及 Koopman/EDMD、稀疏辨识、神经 ODE、物理约束学习和强化学习的经典入门方法，均按相应方法的历史和适用条件介绍。不能仅因安排在后部研究篇就称为“最新前沿”。

研究专题在成熟方法基础上选择一个具体、可复现的问题。每个专题必须包含：问题与已有基线、所用原始论文及版本、研究结论与假设、必要数学补充、固定教学数据或明确的课程实验、代码和运行环境、预算、评价指标、复现实验、消融、失败例与适用范围。

专题更新时同时检查参考文献、核心结论、环境兼容性和实验结果；修改记录进入 ROADMAP。结果只支持实际检查过的任务与条件，不能由单个案例宣称方法普遍优越。


第 17 篇固定两个必做专题：R18 的 [arXiv:1509.03580v1](https://arxiv.org/abs/1509.03580v1) 与 R19 的 [arXiv:1806.07366v1](https://arxiv.org/abs/1806.07366v1)。正式实施先逐项锁定其中一个低维原始实验的方程、数据、评价与预算，再实现生命系统改编。15.3 完整建立低维伴随方程和梯度核验，17.2 据此复现原论文方法；固定离散求导作为数值对照或方法改编单列，不得以改编结果冒充原方法复现。原论文/代码版本、课程改动与失败结果随复现 Notebook 记录。
