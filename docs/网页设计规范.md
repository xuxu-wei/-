# 网页设计规范

设计修订日期：2026-09-18。本文规定全书配套网页的职责、信息结构、页面模板、配色和交互规范；题型契约、本地 API、Python 执行与 JSON 记录见[交互练习与判题系统设计](交互练习与判题系统设计.md)。课程目录及目标见[教材设计](教材设计.md)，实际交付与验收统一见 [ROADMAP](../ROADMAP.md)。正式篇章与制作样章使用独立内容身份，共用导航、编辑器和本机执行组件。

网页是整个本地教材的交互界面，使用当前本机 Python 程序提供的页面与接口。仅考虑 PC 使用场景，优先桌面窗口及鼠标、键盘操作，不安排手机或平板专项适配。视觉采用纯白背景和指定蓝红界面色系；数据曲线另用鲜蓝、玫红等易区分的色板，具体值统一维护在[视觉规范](#visual-design)和[图表配色](#chart-colors)。

## 1. 网页职责与页面层级

**每篇有篇首页，每章有独立章节页面；每章页面同时承载概念导览、按需可视化/playground 和该章全部交互练习入口。** 可视化模块与 playground 可按教学收益取舍，章节页面和练习入口不可省略。章导览列出学习重点、难点、知识体系、先修与 Notebook 入口；它与可视化、练习使用同一页面框架和目录。无可视化需求的章不添加空模块。

| 页面 | 建议稳定路由 | 必备内容 |
|---|---|---|
| 全书目录 | `/` | 项目与学习入口、十二篇目录、本地启动方式及连接状态 |
| 篇首页 | `/parts/02-系统随时间演化/` | 本篇目标、先修、章目录、题型数量、篇内练习进度、篇末综合题组入口 |
| 章节页 | `/chapters/02-01-用递推描述增长与清除/` | 学习目标、Notebook 小节链接、概念导览、可视化/playground（如需）、章练习和前后章导航 |
| 篇末综合题组 | `/parts/02/practice/` | 共享案例、目标、题目清单和同样的选择/代码答题组件；不出现报告上传 |
| 题目深链 | 章节练习路由加 `?question=描述性题目名` | 直接选中题目，保留篇章上下文；刷新、复制和浏览器前进后退均可恢复 |

12 篇全部交付后至少形成 12 个篇首页、55 个章节页和 12 个篇末题组页，加全书目录共 80 个标准页面。实施按篇推进，未交付章显示“待发布”，不以空白占位页充当完成。题目专注模式属于同一章节页的展示状态，不再复制一套题面或独立进度。

以上为本机地址下的页面路径，统一入口由现有 `tools/serve.py` 扩展提供；直接打开或刷新章节 URL 必须返回对应页面。样章独立路由为 `/samples/accumulation-clearance/`，其下 `explore/` 与 `practice/` 分别提供可视化和练习；旧 `/web/single-compartment/` 与 `/practice/m1/` 仅兼容跳转到样章，不指向正式章节。

Notebook 仍完整承载数学解释、代码、图示、练习题面和公开样例，离线可读可运行。网页说明概念、组织交互与本地客观判定，并双向链接到具体 Notebook 小节。依赖和教材材料准备好后，正常学习与判题无需联网。不可将必要数学只放在网页，也不可在页面上放一条含糊的“去做练习”链接而没有题目清单和实际答题入口。

Notebook 中的网页入口必须使用本机 HTTP 地址，例如 `http://127.0.0.1:8000/samples/accumulation-clearance/explore/`；题目入口使用 `http://127.0.0.1:8000/samples/accumulation-clearance/practice/?question=stock-flow-units` 一类稳定深链接。不得将相对 `.html` 或 `file://` 文件路径作为学习入口，也不使用“可视化文件”这样的源码入口名称。HTTP 服务须返回正确的 `text/html` 类型；验收从渲染后的 Notebook 实际点击，确认看到页面、图形和控件，不能只检查路径存在。

### 1.1 Notebook 的打开方式

网页所有 Notebook 主入口均为“在默认 IDE 中打开”，通过本机同源接口按目录中的小节 ID 请求操作系统打开项目原文件；不默认导航到浏览器 Notebook、下载副本或写死某个 IDE。系统已有的 `.ipynb` 文件关联决定应用，不自动修改关联设置。学习者仍可自行选择其他 Notebook 阅读方式。

按钮具有连接中、可用、请求中和失败反馈。未连接时说明启动/重新连接方法；本机程序确认请求后显示“已请求系统默认 IDE 打开”，不把操作系统的请求接收当作文件已执行。默认应用缺失或打开失败时显示操作提示，不能静默退回浏览器或下载。Notebook 提供返回本机可视化的入口。

本机接口只接受目录中的 Notebook ID，不接受页面传入任意路径或命令；只监听本机，检查请求来源与会话令牌。自动检查核对所有 ID 与文件映射、失败反馈和不跳转行为；验收时另用真实点击确认本机默认 IDE 打开原文件，记录操作系统与实际 IDE。

## 2. 统一页面模板

### 2.1 全站框架

- 页首：教材名称、全书目录、当前篇章；保持轻量，不加入与学习无关的运营模块。
- 桌面左侧：全书十二篇的展开目录，按篇—章—小节组织；当前页面自动展开祖先分支并定位当前项，当前项有背景、侧边标记及 `aria-current`。样章在正式目录之外单列。所有条目可按需访问，进度不锁定导航。
- 目录可通过页首常驻按钮隐藏/展开，隐藏后主体立即使用腾出的宽度；可拖动目录右缘调整宽度，分隔线可聚焦并支持左右键、Home/End、Enter 或双击恢复默认。目录内按 Escape 隐藏并将焦点交回按钮。隐藏状态、目录宽度在本浏览器内跨页/刷新保留；窄窗口限制实际宽度，不能把主体挤出屏幕。
- 全书目录的每张篇卡片显示“第 N 篇 + 篇名”，篇目录的每张章卡片显示“篇.章 + 章名”（如 1.1），并与侧栏保持一致。正式篇章顺序编号帮助定位；S01/E01 等维护编码仍不进入学生界面。
- 导览首屏压缩面包屑、标题与状态提示的重复留白。篇卡片同时呈现章节主题，章卡片呈现学习目标和先修；整张卡片可点击且焦点清楚。篇卡片按主体可用宽度采用 1—4 列，章卡片按约 360 px 的可读最小宽度自动排列；不用固定最小高度撑空内容，不为填满屏幕重复文案。长标题完整换行，避免截断教学信息。章内目标、先修并列，重点与知识顺序按内容衔接。
- 目录进度：无有效作答为灰色“未开始”；存在当前版本有效尝试而未全部通过为橙色“进行中”；全部已交付必做题当前版本完整通过为浅蓝色“已完成”。示例试算可产生尝试状态但不算完成；系统错误、中断、取消、未保存和旧版记录不冒充有效进度。无已交付题目的篇章保持未开始，不能把 0/0 判为完成。目录、章节、练习同步读取本机 JSON 汇总，提交后及重新进入页面立即刷新，页面可见时每 15 秒更新一次；题目列表、章进度与目录使用同一汇总结果。
- 内容顶部：面包屑、唯一 H1、学习目标、先修复习链接、Notebook 入口及本章练习数量。
- 目标区只写学习目标与先修。网页安排、运行配置、实现进度和制作说明不得进入该区域；连接错误和恢复操作使用独立提示。术语首现遵循[教材术语规范](教材设计.md#terminology-style)，每个可独立访问的概念页与题目就地标注。
- 内容顶部固定同一组显眼切换按钮：“本章导览 / 可视化与探索 / 练习”。活动项深蓝底白字；切换保留章节上下文，hover 轻微上移、背景和阴影渐变。练习内部用小节标题选择与题目标题导航，保持草稿与作答记录。尚未交付的能力不显示可用按钮。
- 页尾：本章回顾、上一章/下一章、篇首页与对应 Notebook；长页面提供跳转到练习和返回顶部。

### 2.2 篇首页

首屏回答“本篇解决什么问题、开始前需要什么、学完能做什么”。目标对应大纲 T1—T4，章目录显示标题、目标摘要、选择题/计算题数量与状态。实际学习时间未测量时写“待试学估算”，不自动估出时长。

练习进度以当前版本必做题的通过数为分母，分开显示“章练习”和“篇末题组”；可筛选未做、未通过、已通过、待重做。阅读、打开可视化或看过解析不自动算题目通过。进度不作为解锁先修章节的硬门槛，自学者可以自由导航。

### 2.3 章节页与练习工作区

```text
教材 / 第 2 篇 / 2.1 用递推描述增长与清除
┌ 本章目标 · 先修复习 · Notebook 小节入口 · 已通过 1/3 ┐
│ 概念导览：模型、变量单位、必要假设                   │
│ 可视化 / playground（本章有需要时）                 │
├ 交互练习：题目选择 · 题型 · 目标 · 题目版本          ┤
│ 题面、输入输出、限制、样例 │ 本次结果：摘要、调试详情 │
│ 提示、复习链接             │ 选项或 Python 编辑器     │
│                           │ 运行样例 / 提交判定       │
└ 上一章 · 篇末综合题组 · 下一章                       ┘
```

练习工作区在足够宽时左右分栏：左侧题面，右侧选项/编辑器；分隔线可拖动或用键盘调整，两栏分别滚动，编辑器填充随浏览器高度变化的答题面板。小节选择与标题紧凑并排，避免无意义的顶部留白。示例试算与提交结果在代码区上方展开，完成时以短暂淡入/上移动效提示，并将结果滚动到可见位置；结果不自动消失，可收起和再次展开。长 traceback 或用例详情在面板内部滚动，不覆盖代码。运行状态与取消入口也在上方，不只更新页底；用户继续输入时不转移键盘焦点。收起全站目录可扩展编辑空间，保留题目、草稿与结果。按扣除目录后的实际可用宽度决定是否改为上下排列；单栏答题区仍占满宽度，提交按钮不能遮住代码或错误信息。

题面必须显示：题型（单选/多选/Python 计算）、小节及题目标题、必要的自然顺序（如“第 2 题”）、目标、问题、假设与单位、作答要求；代码题再显示函数契约、输入输出、允许库、运行限制和误差规则。需要下载的数据给出文件说明和校验信息。是否允许多选、返回值是否包括初值、列表顺序是否重要都必须在题面直接说明。

## 3. 两类题的标准交互

### 3.1 选择题

1. 单选用单选框，多选用复选框，整行选项可点击；数学和图像选项必须有可理解的文本描述。
2. 选择后不立即泄露答案；点击“提交答案”才发送本次选项集合。未选择时提示“请先选择答案”，不发空请求。
3. 返回后显示“回答正确”或“回答不正确”，并同时标记本次选择与正确集合；展示每项为什么对/错、关键推导、常见误解和复习链接。
4. 修改选项后显示“已修改，待重新提交”；旧解析保留并注明它属于上次提交，不显示为新答案的判定。允许反复学习重试，发送中防止重复点击，同一请求 ID 不重复记录。

回答不正确时，摘要文字为 `--ui-error`，详情为 `--ui-error-strong`，整张反馈卡为错误红色 8% 透明底及 24% 透明边框。系统错误、中断和取消使用中性提示。

解析采用教学语言，不能只有“正确答案是 A”。多选漏选或多选都按完整集合判定，不添加第三种拖拽、填空或自由文本交互题型。

### 3.2 Python 计算题

- 题面直接展示逐题定义的 `def solve(具名参数)`，编辑器预置完全相同的带类型签名；例如 `solve(A0, durations, inflows, outflows)`。参数说明表列出名称、类型、含义与单位，返回值说明类型及顺序，计算规则和约束分别列出。禁止把所有输入藏在 `payload`、通用 `data` 或任意参数包装中；读者无需解析判题协议。语言固定为 Python，不展示无效的多语言菜单。
- 草稿按当前站点来源、题号和版本保存；接口变化升版本，新模板不能套用旧稿或旧成绩。保留旧草稿并提供下载入口；题目切换不丢失当前版本草稿，清除浏览器数据或更换端口/浏览器时不保证草稿保留。
- 两个操作固定为“用示例试算”和“提交判定”。前者只运行样例，不更新通过进度；后者运行完整测试并保存本地记录。两者均由本机程序启动教材 Python 子进程执行，进度从 JSON 作答记录汇总。
- 编辑器使用本地提供的 CodeMirror 5.65.20（MIT），启用 Python 3 模式、Monokai 配色、行号与括号匹配高亮。输入左括号自动补全，已有闭括号支持跳过，空括号支持成对删除；Tab 在四列缩进位插入空格或缩进所选整行，Shift+Tab 反缩进，Enter 延续缩进并识别代码块。行首 Backspace 删除到上一个四列缩进位，混合空格/Tab 按显示列处理；普通代码与选区按正常编辑方式删除。Esc 后 Tab 移出编辑器，不形成键盘陷阱，保留撤销、重做、草稿恢复和中文输入。组件加载失败时明确提示，并退回能编辑和提交的普通文本框。
- 编辑器组件位于 `web/vendor/codemirror/`，保留许可证、来源、固定版本和文件摘要；继续使用 HTML/CSS/ES Modules，不增加读者的前端构建步骤或运行时网络依赖。升级时重新检查输入、选区、撤销、换行、草稿、布局和判题反馈，不能仅换皮肤后宣布编辑体验可用。
- 编辑器、函数签名与样例代码默认自动软换行，长标识符或连续数字不得撑宽整页；编辑区提供显式换行开关，关闭后仅代码区域横向滚动。显示换行不向源码插入换行符，不改变 Python 缩进、复制、下载或提交内容；题面说明始终自然换行。分栏比例和换行偏好跨题与刷新保留，保存布局不触碰草稿或作答记录。
- 待提交状态下可复制、下载 `.py`、恢复模板；恢复模板会覆盖当前草稿，需给出撤销或明确的二次操作。自动保存不能默默覆盖另一题或另一版本草稿。
- 提交后锁定的是源码快照，编辑器可继续修改；修改后显示“当前草稿与本次提交不同”，结果旁显示提交时间和版本，避免把旧的通过状态贴到新代码。
- “输入样例”和“输出样例”分别采用**说明表格 + Python 代码**：先解释含义与单位，输入侧逐个赋值，例如 `A0=2`、`durations=[...]`，然后直接调用 `solve(A0, durations, inflows, outflows)`；输出侧展示 `expected_output` 的实际列表、标量或有明确定义的元组。禁止改成 `example_input` 字典后整体传入。每组样例补充数值怎样得出的简短解释。提供各自的复制按钮及成功/失败反馈；复制不覆盖草稿，调用放在已完成的函数定义之后。
- 表格与代码从同一份题库样例生成，序列顺序一致；表格可将长小数标为近似值，Python 代码保留样例原始精度，并提示按题面容差比较。不以整块 payload/expected 协议 JSON 替代教学解释，也不以可读性为由删除代码。两个样例分别默认折叠；表格限高 220 px、代码限高 240 px，各自滚动；代码至少 14 px。大对象不得遮盖题干或编辑区；学生界面不再以“公开样例”为标题。
- 结果显示通过数、失败类别和首个失败用例。样例显示输入、期望值、实际值、差异和截断日志；补充测试详情默认折叠，可展开复盘。测试材料随教材保存在本机，折叠是教学展示安排，不宣称保密。
- Python 语法错误直接显示 `answer.py` 文件名、行号、源码、Python 提供的指示箭头与异常名称；运行异常提供 traceback 及学习者调用链，保留异常因果链，不能只写一句“运行失败”。调试文本可复制、可手动选取，并提供“定位出错行”按钮及编辑器行标记。行号属于本次提交快照，修改草稿后停用定位并移除旧行标记。超时、输出超限和系统错误按实际原因解释，不伪造 Python traceback。
- 语法和运行错误可定位到提交代码行；超限反馈解释哪项实际限制触发；环境缺失、内部故障和保存失败提供对应恢复提示，不显示“答案错误”。图表中的玫红数据系列不自动表示答题错误。

### 3.3 状态与异常统一规范

| 状态 | 必须显示 | 可操作内容 |
|---|---|---|
| 未作答 / 有草稿 | 题面、输入位置、未提交提示 | 编辑、查看输入与预期输出、提交 |
| 请求发送中 | 正在提交，防止重复点击 | 可继续编辑，不能重复创建同一请求 |
| 准备 / 运行 / 判定 | 阶段名称与耗时，不伪造完成百分比 | 查询、取消、离开后返回查看 |
| 另一个计算任务运行中 | 当前任务入口；本机一次执行一个计算任务，无排队 | 查看当前任务，等待或主动取消后再提交；仍可编辑和做选择题 |
| 已通过 / 未通过 | 判定摘要、对应源码/选项快照、解析或差异 | 修改、再次运行/提交、复习 |
| 请求中断 / 查询失败 | 草稿仍在；明确本次提交是否已被接收 | 恢复连接后以原请求 ID 查询，不盲目创建新提交 |
| 本地程序未连接 | 本机启动方法和重新连接入口，不提示互联网服务故障 | 已加载的阅读、可视化与草稿编辑可继续，代码可下载；刷新或打开新页面需要本地程序运行 |
| 题目改版 | 当前草稿属旧版，旧结果保留 | 比较变更、复制草稿到新版再提交 |
| 已取消 / 执行中断 / 系统错误 | 与答错不同的文案，不增加错误次数 | 取消须得到进程已回收的确认；重启后未完成任务标记中断，由读者重新提交 |
| 记录未保存 / 损坏 | 明确标注未保存结果或不完整进度，不能虚报已完成 | 保留可恢复的草稿与结果，按本地文件提示处理后重试 |

篇末题组使用同样的组件和反馈语义。题组通过表示其中全部必做题的当前版本曾通过；不采用自由报告或人工总分。

## 4. 可视化与 playground 规范

每个可视化模块依次呈现“要观察的问题、变量与假设、事前预测提示、控件、图形/数值、解释、相关题目”。题目引用某个可视化场景时固定参数快照和模型版本，提交后即使读者继续拖动控件，也不改变已提交题目的条件。

控件必须有名称、单位、合法范围和默认值；提供重置、键盘操作及清晰的播放/暂停。动画帧率只改变展示速度，模型步长单独说明。参数更新后只重算受影响内容；过密更新可以节流，但图中必须区分正在计算与最终结果。

播放按钮在交互初始化完成、事件绑定和首帧绘制成功后启用。加载失败或超时必须显示可操作的提示，不能留下看似可用却点击无反应的按钮。播放后时间读数与可观察图形同步变化；暂停冻结当前状态，终点可重播，修改模型参数按说明重置。以实际经过时间推进显示，延迟帧由备用调度补齐，旧回调不能造成重复加速；切离页面时如暂停，应显示原因。首次打开默认暂停，减弱动效偏好不妨碍读者手动定位时间。

动画验收包含真实鼠标点击、键盘操作、时间与图形确实变化、暂停后保持不变、终点重播、快速切换、延迟绘制及模块加载失败；不能只检查按钮文字或数学函数。M1 的动画采用解析轨迹，数值步长只影响独立的 Euler 对照面板。

成对示例使用可往返的状态切换：按钮显示下一次将进入的示例，邻近说明显示当前示例、参数与观察重点。示例改变哪些条件必须明确，单变量对照保留其余条件。手动调参、其他预设、步长调整和重置后，从实际参数重新识别状态，不能沿用过期标签。样章的正负值对照固定 u=0、k=0.75、A₀=10，以 h=2 的负值示例与 h=1 的正值示例往返比较；切换暂停并回到 t=0。验收至少连续往返两次，并交替操作减小步长、手动参数和重置。只有单向载入而无明显返回操作不能通过。

曲线有坐标、单位、图例与数据摘要；采用[独立图表色板](#chart-colors)，同时使用线型和标记。复杂图提供相应数值表或可下载数据。非有限结果停止计算并解释，数值负值或发散作为失败案例时保留标注，不裁剪成看似正常的轨迹。已加载的浏览器可视化在本地接口断开后应尽可能仍可使用，计算题另行显示连接状态。

网页与 Notebook 引用同一模型契约、默认参数及核验情形；实现可分别使用 JavaScript 与 Python，但须交叉核验。可复制改编样章算法；正式教材不导入样章文件。播放、配色、导航等共用组件放在通用目录，样章专属页面和旧路由按 ROADMAP 的清理节点移除。

## 5. 视觉、排版与可访问性

全书共享样式变量和组件。首版固定为纯白背景，界面使用用户指定的蓝红色系，数据图表使用独立色板；每篇沿用同一导航、排版和结果组件。以下为实现基线，任何调整均须同步本规范并复查可访问性：

| 项目 | 统一规范 |
|---|---|
| 布局 | 主体无固定最大宽度，横向边距 16—28 px；使用目录之外的全部空间。目录默认 284 px，可在 220—480 px 内调宽并可完全隐藏，窗口缩小时为主体至少保留约 600 px。双栏默认题面 48%、答题 52%，调节时每栏至少约 300 px；编辑器占据面板剩余高度 |
| PC 窗口布局 | 内容可用宽度 ≥760 px 时练习双栏，否则题面在前、答题在后，结果始终位于代码区上方；上下布局的答题区仍占满宽度，不再设 760 px 上限。目录卡片根据主体宽度重排列数。检查 1024、1366、1440、1920、2560 px 及目录显示/隐藏、宽度极值；短窗口允许页面纵向滚动，不截掉提交按钮。不设置手机适配验收项 |
| 字体 | 中文系统无衬线字体，正文 16—18 px、行高约 1.7；代码等宽 14—16 px；标题用层级而非只用颜色区分 |
| 间距 | 4 px 基础间距，常用 8/12/16/24/32；内容区和控件保持一致内边距 |
| 色彩 | 页面、导航和图表为 `#ffffff`；源码编辑器与 traceback 为 Monokai 深底 `#272822`、基础文字 `#f8f8f2`；Python 关键字、函数、字符串、数字分别高亮，注释保持可读。其余交互面板允许既定蓝色的低透明度底，反馈按语义着色；状态配图标和文字 |
| 控件 | 主要操作目标至少 44×44 CSS px；清楚的悬停、键盘焦点、禁用及忙碌状态；不依赖 hover 才能读答案 |
| 公式与表格 | 可选择文本或可访问数学表达；正文、代码默认换行，确需横向滚动的宽表和关闭换行后的代码只在自身区域滚动，提供标题与字段含义 |
| 动效 | hover/焦点/选中 180—250 ms，页面进入 380 ms；缓动 cubic-bezier(.2,.75,.25,1)，位移不超过 7 px；不使用持续跳动、闪烁或大幅缩放；尊重 prefers-reduced-motion。教学动画只在主动播放后运动，暂停精确停留；示意粒子首尾渐隐避免硬跳 |

### 5.2 数据曲线、色标与两端一致性

默认两条数据线采用 SHAP 的鲜蓝与玫红端点；三个额外彩色是本项目为多曲线对照选择的扩展，深灰留给参考线。前两个十六进制值由 SHAP 源码中的 Lch 端点换算并取整，配色使用不增加 SHAP 运行依赖。[SHAP 颜色定义](https://github.com/shap/shap/blob/master/shap/plots/colors/_colors.py)、[SHAP 色彩空间转换](https://github.com/shap/shap/blob/master/shap/plots/colors/_colorconv.py)

| 样式变量 | 色值 | 默认用途 | 建议线型与标记 | 与纯白的对比度（约） |
|---|---|---|---|---|
| `--data-1` | `#008bfb` | 第一条数据线，鲜蓝 | 实线、圆点 | 3.45:1 |
| `--data-2` | `#ff0051` | 第二条数据线，玫红 | 虚线、方点 | 3.91:1 |
| `--data-3` | `#009e73` | 第三条数据线，绿色 | 点划线、三角 | 3.42:1 |
| `--data-4` | `#d55e00` | 第四条数据线，橙色 | 点线、菱形 | 3.87:1 |
| `--data-5` | `#7c52ff` | 第五条数据线，紫色 | 长短划线、倒三角 | 4.66:1 |
| `--data-reference` | `#555555` | 基准、阈值及理论参考水平线 | 细虚线，无标记 | 7.46:1 |

图表采用白色画布。网页主数据线宽 2.5—3 px，参考线约 1.5 px；Notebook 绘图按显示与导出尺寸匹配可辨识效果。图例文字和坐标文字使用界面深色，以彩色线段/标记示意系列，不能把仅满足图形对比要求的数据色直接用于小号正文。置信区间可用对应曲线色的浅透明填充，边界与主曲线保持清晰；网格线为辅助装饰，不与数据争夺注意力。

数据映射规则：

1. 默认两曲线对照使用鲜蓝和玫红；三至五条再加入绿、橙、紫。M1 的方法对照图中解析轨迹用鲜蓝，Euler 数值轨迹用玫红虚线，平衡参考用深灰；仅比较参数条件的图按条件区分，并在图例中明确含义。
2. 同一案例的变量或方法使用稳定的系列 ID 与颜色映射，网页、Notebook、图例和导出图一致；隐藏某条线、切换排序或拖动参数不重排其他系列的颜色。
3. 每条曲线同时有明确图例，并用线型或稀疏标记辅助区分，密集数据不逐点叠满标记。超过五条彩色数据线时优先拆成子图或让读者选择要比较的系列，不能继续堆叠相近蓝色。
4. 连续数值使用明确的色标、范围和单位，不把类别色轮当作连续尺度。单向大小可用指定蓝色由浅到深的顺序色标；围绕有意义零点的偏差可用蓝—白—玫红发散色标，并标明中心。
5. 图表的玫红表示系列或色标中的数值含义，不自动表示错误或危险；若要标记失效区间，必须另加区域、图标或文字解释。

以上为全书统一的网页与 Notebook 图形规范。共享定义位于 `src/systems_science/theme.json`；教学包直接读取，`tools/sync_theme.py` 输出网页 CSS/ES Module，`--check` 检查是否同步。受影响的 Notebook 重新执行并检查保存的图像；实际完成范围以验收记录为准。

### 5.3 可访问性

以 WCAG 2.2 AA 为验收目标，包括键盘操作、可见且不被遮挡的焦点、正文对比度至少 4.5:1、大字至少 3:1，以及可识别控件边界。项目选择的 44 px 点击目标高于 2.5.8 通常要求的 24 px 最小尺寸；不能据此免去间距、焦点和实际操作检查。[WCAG 2.2](https://www.w3.org/TR/WCAG22/)、[目标尺寸解释](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

必要的控件边界和图形与相邻颜色至少达到 3:1；颜色之外仍须有形状、文字或线型等线索。上表中的白底计算不替代多曲线重叠、选中背景、透明填充和不同视觉条件下的实际检查。[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

实现使用语义化 `nav`、`main`、标题、表单 `fieldset/legend` 与按钮。异步状态通过简短 live region 播报，完整解析作为普通内容可逐项阅读；不在每次轮询时反复朗读整份结果。提交后将关注引导到结果摘要，但不在用户继续编辑时反复抢焦点。

编辑器必须能用键盘进入和离开，并有明确的缩进/焦点切换提示与退出操作，编辑区域标注多行文本框及名称；组件不可用时退回普通文本框，不能形成 Tab 键陷阱。目录抽屉管理焦点并支持 Escape 关闭；导航展开状态、选项状态和错误提示能被辅助技术识别。

## 6. 前端模块与数据边界

以统一目录清单生成篇首页和章页面，由共享 ES Modules 组件渲染练习，不手工复制 55 套判题界面。首版沿用现有 HTML/CSS/JavaScript 展示基础，职责固定如下：

| 模块 | 职责 |
|---|---|
| `SiteShell` / `ChapterNav` | 全站结构、当前路径、前后章、响应式目录 |
| `LearningHeader` / `ModelCard` | 目标、先修、变量、单位、假设、Notebook 链接 |
| `VisualizationHost` | 加载声明的概念组件，管理参数和重置，不持有判题答案 |
| `ExerciseList` / `ExerciseWorkspace` | 题型筛选、深链、题面与专注模式 |
| `ChoiceForm` / `PythonEditor` | 两类题输入及本地草稿；不自行决定正式通过 |
| `SubmissionStatus` / `ResultPanel` | 本地任务状态、用例差异/逐项解析、重试和取消 |
| `ProgressSummary` | 从本地 JSON 记录汇总的题目版本进度，区分浏览器草稿、样例运行与已保存的完整判定 |

页面内容、题目 ID 与 Notebook 导航来自同一清单；网页通过本机同源 API 读取题面与记录，不直接读写学习记录目录。每次启动的请求令牌只在页面内存中保存，相关接口响应不缓存；请求中断后恢复连接并查询原任务。源码、日志和结果按文本处理，不执行提交中的 HTML/JavaScript。

本地程序停止时，已加载内容和浏览器可视化可继续使用，但刷新、新页面与代码提交需要重新启动程序。代码可下载后自行运行；网页只有取得本地判定器保存的完整结果，才显示该版本已完成，不把样例结果、旧快照或断开前的状态当作新提交通过。

## 7. 发布检查与 M1 迁移

每篇交付时逐章检查以下事项，结果写入 ROADMAP 对应里程碑：

1. 每章有真实页面、目标和 Notebook 小节入口；篇/章练习与篇末题组全部有稳定题号和可达入口，往返链接有效。
2. 两类题覆盖首次作答、答错重试、修改后再提交、版本更新与本地程序未连接；选择题完整解析、计算题真实执行与反馈符合本地 API 契约。
3. PC 的常用窗口宽度及文字放大时没有控件遮挡；实际拖动目录和双栏、用键盘调宽、隐藏/展开并刷新、跨页，确认设置保留和主体利用腾出的空间。目录内 Escape 关闭后恢复按钮焦点；长代码软换行不改变草稿，展开样例不撑宽整页；目录变化后图表按容器重绘。图与状态不只靠颜色表达，不安排手机、平板专项验收。
4. 每个可视化的默认、边界、重置和异常值均有检查，与 Notebook 的模型、单位和结果一致；动画有实际播放、暂停、重播及失败场景证据，Notebook 按钮有真实默认 IDE 打开证据。
5. 草稿恢复、题目深链、浏览器后退、请求中断及异步结果绑定正确；多个标签页不会串题或重复执行，程序重启后历史与进度可恢复。
6. 背景、界面颜色、图表色板和状态使用符合统一规范；网页与 Notebook 中同一案例的变量/方法颜色相同，曲线另有线型或点形区分。默认、悬停、焦点、选中、禁用和答题反馈状态均检查对比度。

正式教材与样章的导览、可视化、练习共享 `web/shared/course-shell.*`；按各章已交付课节显示入口，只有对应可视化存在才显示探索按钮。篇末题组计入本篇完成状态，样章记录始终独立。未交付章节仍只提供设计导览，不能由目录存在推断已完成。发布按[教材制作检查表](教材制作检查表.md)保存内容与实际点击证据。
